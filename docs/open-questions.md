# Open questions and operator decisions

Two lists. A: questions to put to the organizers at kickoff (10:00-10:30 IST, Sunday 2026-10-18). B: decisions the operator
makes, each with a deadline. The runbook is [plan.md](plan.md), and the reasons are in [research.md](research.md).

Neither public page answers the questions below. Both pages specify the deliverables, the rubric and the schedule. They do
not specify latency or timeout limits, scorer concurrency, how sources are matched, the "don't know" format, submission
mechanics, whether the endpoint must stay live during scoring, or a policy on pre-existing code ([event page][ev],
[challenges page][ch]).

## A. Questions for the organizers at kickoff

Ordered by impact on the score. K1-K6 are the short list in [plan.md section 2](plan.md#2-event-morning-before-1030).
Write each answer into the event repo's `CLAUDE.md` under "Kickoff answers" before the teammates are spawned.

## B. Operator decisions

"Memo" is the lead's design memo. Its reasons are carried into [research.md](research.md). `PENDING(x)` would mark a
recommendation that waits for a research report or a POC number; none remain in this version.

| ID | Decision | Options | Recommendation | Deadline |
|---|---|---|---|---|
| D1 | Host: primary, fallback, emergency | Google Cloud Run in asia-south1 (Mumbai); DigitalOcean App Platform in BLR; an ngrok free dev domain from the laptop; a Hugging Face Docker Space (only with PRO); Cloudflare quick tunnels, Fly.io and Render free (avoid) | Lead: **Cloud Run asia-south1 is primary**: 41.5 ms round trip vs 261.7-387.9 ms to US and EU, min-instances=1 idles at about $0.65 a day at the default 2 GiB ($0.43 at 1 GiB, $1.08 at 4 GiB; research.md §5.5), remote builds, HTTP probes. It **needs a billing account**. Size: 1 vCPU, min-instances 1, and 2 GiB by default (headroom for onnxruntime arena growth under bursts); 1 GiB is the minimum; 4 GiB for the bge-base upgrade or a reranker experiment. **DigitalOcean App Platform BLR is the fallback**, sized the same way ($12 a month for 1 GiB, billed per second; AMD64 images); SSE there is unverified, so the widget falls back to `/ask`. **An ngrok dev domain is the emergency path**, not a quick tunnel. Quick tunnels have no SSE and random URLs ([quick tunnels][tunnel]); Fly has no India region; Render free spins down; HF Docker needs PRO ([HF Spaces][hf]) ([research.md §5.5](research.md#55-host), [stack report][r-stack]). **Question for the operator: which of these accounts exist, with billing?** | Before Sunday (Saturday dry run, plan section 1.4) |
| D2 | Reuse code from `poc/` at the event? | (a) Build fresh from the briefs. `poc/` serves only as a reference for measured parameters (chunk sizes, model IDs, thresholds); nothing is copied. (b) Port `poc/` modules (ingest, chunker), but only after telling the organizers at kickoff (K6) that the operator is not competing for prizes. The lead estimates this saves about 45 minutes, to spend on stretch goals: a low-confidence agentic escalation, translating non-English questions, more outside sources | Lead: **(a), build fresh**. MLH's standard rules put all work inside the event and forbid re-using code or other project materials ([MLH rules][mlh]). The plan section 3 timeline fits a fresh build, and the real experiment is how far agents get in 4 hours. Disclose in the README either way. The Saturday rehearsal code is thrown away (plan section 1.6) | At kickoff (K6) |
| D3 | Answer model | The candidates table below (from the [stack report][r-stack]) | Lead: choose by measurement at 11:30-12:30, not by brand, using what K1 says the credits cover. **Gemini credits**: try gemini-3.8-flash at reasoning low, gemini-3-flash-preview (non-reasoning) and gemini-3.5-flash-lite at minimal. **DigitalOcean credits**: try gpt-oss-120b at reasoning low and gemma-4-31B-it. **Other providers**: their fast non-reasoning tier. On a fixed 20-row eval subset, pick the highest must-mention coverage among models with citation-format adherence ≥ 95% and p50 ≤ 3 s (**targets**); ties go to the cheaper model. Latency decides: answers cost only $0.0004-0.0045, while time to first token ranges from 0.4 to 24 s with the reasoning setting. The chain is always the credits, then the operator's paid key (D7), then Gemma on the Gemini free tier. Use Gemma 4 as the primary only if the operator wants the "Best Use of Gemma 4" prize ([challenges page][ch]) | At kickoff (once K1 is answered). Final at the 12:30 checkpoint |
| D4 | Blog posts in the index | Out; in as tier 3, down-weighted and dated | Lead: **off, decided by data**. At full weight the blog chunks dropped retrieval MRR@10 to 0.630 from 0.744; at a 0.5 rank weight they were neutral, 0.743 (`poc/results/retrieval-v2.json`). No upside on the eval set, and a staleness risk: the blog is about 1.8x the docs' size and includes stale 2024-25 posts ([docs-site report][r-docs-site]). It stays a documented opt-in at the 0.5 penalty, for conceptual "why Iceberg" questions only. The 13:00 A/B is dropped from the timeline | Decided |
| D5 | GitHub issues and discussions in the index | Out; bulk; curated | Lead: **curated**. Index 10 troubleshooting answers checked absent from the docs, as tier 2, each cited as "known issue #N". No bulk issues: about a third are bot TODOs, and Discussions has 7 threads with one unanswered Q&A ([repos report][r-repos]) | Decided |
| D6 | Repo license | Apache-2.0; MIT | Lead: **Apache-2.0**. The GitHub API lists all five datazip-inc repos (olake, olake-ui, olake-helm, olake-fusion, olake-docs) as Apache-2.0 (checked 2026-10-16). It meets the DigitalOcean prize's open-source requirement ([challenges page][ch]) and grants a patent license explicitly (section 3 of the [license text][apache]) | Before Sunday (it goes into the kit) |
| D7 | Paid fallback key and budget cap | Hold one paid key with ≥ 100 RPM (an OpenAI key, a Groq developer plan, or a prepaid DigitalOcean balance) with a spend cap; billing alerts on the hosts; a `DAILY_TOKEN_BUDGET` in the app | Lead: **hold one paid fallback key with ≥ 100 RPM and a spend cap**, because free tiers will throttle a scorer burst. Examples: Groq's free plan allows 8K TPM, about 2 requests a minute at 4k tokens; DigitalOcean Tier 1 allows 120 RPM ([research.md §5.1](research.md#51-credits-what-the-event-actually-offers)). Set a billing alert on Google Cloud and DigitalOcean. At $0.0004-0.0045 per answer, even 1,000 answers cost under $5 | Before Sunday |
| D8 | Zero valid citations after generation | Full abstain; answer marked "low confidence" | Lead: **abstain**, decided by data. In the canonical POC run, this rule caused 0 of the 13 false abstains on must-answer rows: the score gate caused 7, the model's answerable=false 5, and the scorer's don't-know pattern on a sourced answer 1 (`poc/results/eval_run-canonical.json`, `abstain_breakdown`). A retrieval score cannot decide abstains (research.md §4.3), so the model's `NO_ANSWER` plus citation validation decides, and the score only short-circuits off-topic questions. The local end-to-end run missed both abstain targets (recall 0.833 vs ≥ 0.90; false-abstain 0.072 vs ≤ 0.05; `poc/results/eval_run-canonical.json`). The event-day levers are in research.md §4.3. In the round-2 run the rule again caused no false abstain (`poc/results/eval_run-canonical-combined.json`). The final policy's end-to-end numbers are measured at checkpoints 2.2 and 2.5 on the day. | Decided |
| D9 | Freshness mechanism, and whether it runs after the freeze | An in-app poller; a scheduled GitHub Action; both; off after the freeze | Lead: **an in-app poller**. Poll the sitemap every 5-10 minutes with `If-None-Match`; on a deploy, re-fetch the docs and re-embed changed chunks. For repos, `git ls-remote` plus the compare API (research.md §3.6). A scheduled Action is not the primary path: schedules run at most every 5 minutes and can be delayed ([repos report][r-repos]). Whether it runs after the freeze follows K5. On Cloud Run the poller needs `--no-cpu-throttling`, or CPU is throttled between requests (research.md §5.5) | Mechanism: decided. After-freeze setting: at kickoff (K5) |
| D10 | URL form in `sources` for repo files | Branch form `https://github.com/datazip-inc/<repo>/blob/master/<path>`; full-SHA permalink with `#La-Lb` (`?plain=1#La-Lb` for Markdown) | Lead: a config switch `SOURCE_URL_STYLE`, **default `branch`**: it is the likelier string match for an unknown grader, and it shows current content. The [repos report][r-repos] recommends SHA links instead, because they are immutable and [GitHub documents][gh-perma] that branch links change. The UI card always shows the SHA permalink | At kickoff (K3) |
| D11 | Index the olake-fusion repo's `docs/` folder (upstream Apache Amoro docs)? | Out; in as a down-weighted `fusion-upstream` tier | Lead: **out**. [olake-fusion][fusion-repo] is a modified hard fork of Apache Amoro, and the upstream docs contradict Fusion's defaults: snapshot expiry is off in Fusion but on upstream, and the target file size is 512 MB vs 128 MB ([repos][r-repos] and [olake-domain][r-olake-domain] reports; [Amoro configurations][amoro-conf]). Use Amoro concepts only through labelled outside pages ("upstream; Fusion may differ"). The Fusion gaps (7 of 23 Fusion pages under 100 tokens, `poc/results/corpus.json`) are covered by fact cards and release notes | Decided |
| D12 | Stub and stale docs pages | Hard-exclude (denylist, logged); keep them with a "stale" flag | Lead: **denylist**, kept in config so it can be reversed. 16 pages (plan Appendix A), including `/docs/core/configs/source/` and `/docs/core/configs/writer/`. Both are short link hubs (1,231 and 1,540 characters of article text when the doc-writer fetched them on 2026-10-16), and source/ still mentions an Oracle "LogMiner setup" although Oracle has no CDC ([olake-domain report][r-olake-domain]). They would compete with the real connector and writer pages | Decided |
